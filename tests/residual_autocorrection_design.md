# 残差自相关修正：测试实现设计

## 目标

验证 skill 中的残差协议能否把“发现自相关”转化为受控实验，而不是自动堆叠滞后项。实现必须同时保证候选资格可判定、训练内选择与最终确认职责分离，以及失败时不会把有严重缺陷的基线包装成通过。

## 冻结计划

在打开 1960 年 holdout 前固定：残差定义、外层训练期、两个内部滚动原点、主指标 MAE、候选生成规则、逐窗残差信号门禁和本演示的最小实用改善 `Δ_min=2%`。2% 只服务于这个测试，不是 skill 的通用默认值。

## 有限候选库

| 候选 | 资格门禁 | 修正形式 |
|---|---|---|
| R0：无修正 | 始终保留。 | 原主模型预测，作为比较与回退基线。 |
| R1：AR(1) 残差 | 训练残差的一阶信号触发。 | 只用训练残差递归预测一步动态。 |
| R2：季节 AR(12) 残差 | 对一阶动态预白化后，季节滞后仍触发，且至少有三个完整周期。 | 只用预声明的季节滞后递归修正。 |

R2 的门禁避免把强 AR(1) 过程自然产生的长滞后相关误认为独立季节证据。更广泛的动态重规格属于新候选计划，不在本自动修正轮中替换 R0。

## 两阶段接口

```text
select_model(outer_train) -> FrozenSelection + inner evidence
confirm_selection(FrozenSelection, outer_train, holdout) -> confirmation evidence
```

`select_model` 的签名没有 holdout 参数。每个修正候选必须在所有要求通过的内部窗口中同时满足：相对 R0 的平均 MAE 改善达到案例阈值、指标有限、同类残差信号已被控制。边界按 `改善 ≥ 2%` 执行，因此 2.00% 通过而 1.99% 不通过。

冻结后，确认阶段只计算 R0 与 `FrozenSelection.candidate`。若冻结候选在相同训练输入下不再具备资格，确认必须失败，而不是静默换模型。

## 失败语义

若没有修正候选通过但严重残差信号仍存在，R0 只能作为计算基线，整体状态为 `needs_revision`；不能写成 `pass-with-notes`。只有残余风险已按预注册边界受到限制且结论同步降级时，才可得到 `partial`。

## 可审计工件

测试输出内部逐窗结果、候选汇总、冻结选择 ID、最终确认指标、预测表、严格 JSON 与图形。`plan_id` 由冻结计划哈希生成；改变训练截止日期、内部原点、主指标、阈值或季节周期会产生新的计划 ID。
