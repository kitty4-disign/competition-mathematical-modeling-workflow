# 残差自相关自动修正：工作流设计

## 设计目标

将“残差自相关”从记录性警告升级为**受控的候选修正规程**。自动化只负责诊断和生成有限的修正候选；是否采用仍由严格时间序列验证决定。该流程不得在最终测试期上调参，不得把相关诊断误作因果解释，也不得用不断增加滞后项掩盖数据、规格或问题定义错误。

## 触发与前置检查

仅对有时间顺序、已经完成数据审计且主模型残差可回链到训练期观测的预测任务启用。先检查：时间排序和目标可得性、残差与真实日期的对齐、缺失/异常/结构断点、是否已遗漏明显季节性或外生变量。然后在**训练期残差**上按预先声明的滞后集合执行 ACF 与白噪声检验；只在诊断达到预设异常阈值时生成修正候选。

若历史长度不足以支撑候选滞后，或发现泄漏、数据错位、明显结构断点，自动流程必须停止并升级为数据/规格级审查，而不是拟合残差模型。

## 有限候选库

候选数由可用训练长度限制，且在查看最终测试期前固定。

| 候选 | 适用条件 | 修正形式 |
|---|---|---|
| R0：无修正 | 必须始终保留。 | 原主模型预测。 |
| R1：非季节 AR 残差 | 低阶残差相关；训练历史足以拟合一至少量预设滞后。 | 用训练期残差的 AR 预测加回主模型预测。 |
| R2：季节残差修正 | 明确周期且至少有三个完整周期；季节滞后诊断触发。 | 在 R1 基础上加入预设季节滞后。 |
| R3：动态重规格候选 | R1/R2 均失败或结构问题明显。 | 例如状态空间或含动态误差的重规格模型；作为新主模型候选，不能自动取代 R0。 |

默认将非季节滞后候选限制在 `1..min(5, floor(n_train/10))`；季节滞后只在历史长度足以覆盖至少三个周期时加入。所有候选必须记录其残差定义、滞后、训练窗、递归预测方式和是否使用外生变量。

## 选择与回退门禁

在训练期内部创建一个或多个**滚动原点验证窗**。先固定主指标和最小实用改善阈值 `Δ_min`；若题目未指定，默认要求主误差相对 R0 改善至少 2%。只有同时满足以下条件的修正候选才可被采纳：

1. 不使用最终时间外测试期、未来目标或未来残差；
2. 在滚动验证的主指标上相对 R0 达到 `Δ_min`；
3. 修正后验证残差诊断不再触发同一严重自相关信号，或已清楚解释为何仍有残余；
4. 修正没有引入违反领域硬约束、数值不稳定或明显复杂度失衡；
5. 结论可由固定数据版本、配置和代码复现。

若没有候选通过，选择 R0 并将最终状态标为 `needs-revision` 或 `pass-with-notes`；不能为了“消除相关性”而采用验证较差的修正。最终时间外测试只能用于一次性确认已在内部验证中选定的模型。

## 需要记录的自动修正日志

| 字段 | 记录内容 |
|---|---|
| 触发 | 残差定义、诊断方法、滞后集合、阈值、训练窗。 |
| 前置审计 | 对齐、泄漏、异常、季节性和结构断点检查。 |
| 候选 | R0–R3、滞后、参数、训练/验证窗、求解状态。 |
| 选择 | 每个窗的主指标、平均改善、残差诊断、接受/拒绝理由。 |
| 最终确认 | 冻结后的最终测试指标、边界检查与结论级别。 |
| 回退 | 未采用修正时的原因、下一层修复动作和禁止的结论。 |
