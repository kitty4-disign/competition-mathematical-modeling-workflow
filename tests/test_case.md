# 更新后数学建模工作流：端到端测试案例

## 测试目标

验证 `competition-mathematical-modeling-workflow` 的新增要求能否在一个真实、小型且可复现的预测任务中被执行并留下完整证据链。测试重点不在追求最优预测精度，而在于检查“候选准入—比较—实现—验证—审计—交付”是否连贯且能阻止不充分候选进入主模型。

## 真实数据与问题

使用公开的 **AirPassengers** 月度客运量序列。数据包含 1949-01 至 1960-12 的 144 条月度记录，字段为 `Month` 与 `Passengers`；原始 CSV 与仓库视图均已核验。[1] [2]

> **测试问题：** 仅使用 1949-01 至 1959-12 的数据，预测 1960 年每月客运量，并与已知真实值进行严格时间外评估。

## 模型候选

| 候选 | 机制 | 角色 | 预期风险 |
|---|---|---|---|
| S1：季节性朴素基线 | 预测值等于上一年同月值。 | 必须比较的基线。 | 无法外推长期趋势。 |
| S2：对数线性趋势 + 月份固定效应 | 在对数客运量上用时间趋势和月份哑变量进行最小二乘拟合。 | 主模型候选。 | 假设趋势在对数尺度近似线性，且季节结构稳定。 |
| S3：仅趋势回归 | 在对数客运量上仅拟合时间趋势。 | 应被淘汰的候选。 | 缺少季节项，无法刻画月度波动。 |

## 验收标准

| 检查项 | 通过标准 |
|---|---|
| 候选准入 | 三个候选都填写目标、数据、假设与复现门禁；S3 必须因遗漏季节性诊断而降级/淘汰。 |
| 可复现实现 | 数据下载、训练/测试切分、模型计算和指标生成均由单一脚本重跑；不使用测试期调参。 |
| 验证 | 提供时间外 MAE、RMSE、MAPE、基线比较、残差诊断、边界检查及局限。 |
| 灵敏度记录 | 对主模型趋势参数做 ±5% 局部扰动，并记录基准、步长、输出变化和解释边界；不将其误述为全局重要性。 |
| 审计 | 每个关键结论可定位到数据、公式、代码输出或测试表；AI/外部实现栏清楚声明本测试未采用 AI 生成模型或第三方预测实现。 |
