# 时间序列残差自相关：候选、选择与回退

仅对具有严格时间顺序的预测任务启用本协议。把自动化限制为生成和检验有限候选；不要把“消除残差相关”当作目标，也不要在最终测试期上挑模型。

## 1. 冻结前置条件

在读取最终测试目标前，冻结：

- 残差定义、训练窗、预测期和主指标；
- 时间对齐、缺失/异常、泄漏、季节性与结构断点审计；
- 诊断方法、滞后集合、显著/实用阈值和候选上限；
- 内部滚动原点、最小实用改善 `Δ_min`、窗口一致性规则和最终测试使用规则。

不要设置跨任务通用的 `Δ_min`。根据题目损失、基线波动、采样不确定性和决策价值确定它；教学或演示案例可预注册 2% 等阈值，但必须标为案例设定而非统计定律。

若时间错位、泄漏、目标不可得、结构断点未处理或历史不足，停止残差建模并回到输入/规格层。

## 2. 用诊断决定候选资格

始终保留 R0。只有对应信号在训练残差上触发时，才生成相应修正：

| 候选 | 资格门禁 | 修正与边界 |
|---|---|---|
| R0：无修正 | 始终保留。 | 原主模型；作为比较和回退基线。 |
| R1：低阶 AR 残差 | 预声明的低阶滞后触发，且样本长度支持该阶数。 | 仅用训练残差递归预测；记录滞后、参数与初值。 |
| R2：季节残差 | 去除已识别的低阶动态后，季节滞后仍触发，且历史至少覆盖三个完整周期。 | 只加入预声明季节项；不得把低阶 AR 的长滞后相关或“存在季节周期”误作独立季节信号。 |
| R3：动态重规格 | R1/R2 失败或证据指向结构性遗漏。 | 作为新主模型候选重新完成准入、规格和验证，不在本轮自动替换 R0。 |

如果整体诊断未触发，只保留 R0。非季节候选阶数上限可用 `min(5, floor(n_train/10))` 约束搜索，但每个实际候选仍要有对应滞后信号。

## 3. 只用训练期内部证据选择

实现两个职责分离的步骤：

```text
select(train_only, frozen_plan) -> FrozenSelection
confirm(FrozenSelection, holdout) -> ConfirmationReport
```

`select` 的接口不得接收最终测试目标。数据允许时至少使用两个滚动原点；每个候选只有同时满足以下条件才可冻结：

1. 在预注册主指标上达到 `Δ_min`，且改善不是由单个窗口独占；
2. 通过预注册的不确定性或窗口一致性检查；
3. 每个要求通过的验证窗中，同类严重残差信号不再触发；若使用“残余已限界”例外，必须在看结果前定义容忍阈值和允许的结论强度；
4. 无数值不稳定、硬约束违反、未来信息或不可复现实现；
5. 复杂度与样本量和实际信息增益相称。

“略低于 R0 的残差相关”不等于通过。边界值按 GateSpec 中写明的闭区间或开区间处理；例如 `改善 ≥ 2%` 时 2.00% 通过、1.99% 不通过。

若多个候选通过，按预注册主指标、复杂度和次级诊断排序；不要在看到最终测试结果后改变顺序。若没有修正候选通过，保留 R0 仅作为计算基线。严重诊断仍存在时将预测主张标为 `invalidated/needs-revision`；只有残余信号已预先限界且结论降级时才能标为 `partial`。

## 4. 冻结后一次确认

最终确认只评估冻结候选和预声明基线。先保存 FrozenSelection 的候选 ID、训练输入版本、计划版本和时间戳，再开放 holdout。

最终结果变差时如实报告，降低或否定主张，但不重选未冻结候选。要继续开发时创建新计划版本和新的未污染验证证据；同一 holdout 不再充当无偏最终确认。

## 5. 必须记录

| 项目 | 最低记录 |
|---|---|
| 触发 | 残差定义、训练窗、诊断、每个滞后阈值与是否触发。 |
| 前置审计 | 对齐、泄漏、异常、季节性、断点和历史长度。 |
| 候选资格 | R0–R3 的生成/禁用理由、参数、状态与失败运行。 |
| 内部选择 | 每个滚动窗的指标、改善、不确定性、残差诊断和接受/拒绝理由。 |
| 冻结证明 | 候选 ID、训练/计划版本、选择输出及 holdout 未进入接口的证据。 |
| 最终确认 | 冻结候选与基线的指标、边界检查、结论强度和回退状态。 |
