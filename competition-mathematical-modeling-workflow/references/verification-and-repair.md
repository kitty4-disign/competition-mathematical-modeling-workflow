# 验证、审计与分层修复

将验证设计为独立阶段，而不是论文末尾的装饰。每一项关键结论必须有**完整谱系、预注册判据、失败条件和唯一修复路由**。

## 目录

1. 证据矩阵
2. 四层审计
3. 最小验证组合与灵敏度
4. 分层修复协议
5. 语义审计
6. 复现与输出

## 1. 证据矩阵

对每个关键主张建立记录；无法填满的主张必须降级为假设、探索性发现或待验证结论。

| 主张 ID | 精确主张 | 输入与假设 | 规格与运行 | 结果与验证 | GateSpec | 结论强度 | 失效条件 |
|---|---|---|---|---|---|---|---|
| C1 | 例如：在情景 S1 下方案 A 比基线节约成本 | `I-data-v2` / `A-v1` | `M-opt-v3` / `RUN-014` | `R-cost-v3` / `G-opt-02` | 成本差≥阈值且全部约束可行 | 强/中/探索性 | 需求超出情景范围 |

证据可取：代数推导、数据描述、交叉验证、时间外测试、可行性检查、基线对比、情景仿真、灵敏度分析、外部事实核对。单个公式、图表或训练内拟合不能单独构成完整证据链；不要用同一训练数据上的拟合优度同时证明预测能力和机制真实性。

## 2. 四层审计

按顺序审计；前一层不通过时，不要用后一层结果掩盖问题。

### 层 A：输入与数据审计

检查文件版本、字段含义、单位、重复记录、缺失机制、异常、样本选择、时间泄漏和数据变换。输出“数据问题—处理—残余风险”表。

### 层 B：模型语义审计

检查题意—变量—目标—约束映射；变量域与单位；目标方向；边界和初值；参数的估计来源；模型何时会产生不合理行为。使用 `references/model-selection-atlas.md` 中的语句—公式台账。

### 层 C：计算与求解审计

检查代码是否实现同一数学模型；随机种子和环境；求解器状态；终止条件；数值尺度；性能瓶颈；图表是否由当前结果生成。对优化问题记录 `optimal / feasible / infeasible / unbounded / time-limit / error`，不得仅报告一个数值。

### 层 D：结论与叙事审计

检查每个结论是否由证据矩阵支持；图表与正文是否一致；是否把相关写成因果；是否夸大外推；局限是否与假设和数据风险对应；论文是否回答全部子问题。

## 3. 最小验证组合

在看结果前，把对应行的每一项写成 GateSpec。对应任务类型的最低组合是合取关系，必须全部通过或有合格豁免；“优先补充”只能增加证据广度，不能替代最低组合。

| 任务 | 最低组合 | 优先补充 |
|---|---|---|
| 预测/分类 | 合理切分 + 基线 + 两个指标 + 误差检查 | 校准、分组性能、时间外测试 |
| 优化 | 可行性 + 基线比较 + 求解状态 + 权重/参数敏感性 | ε-约束/Pareto、情景/鲁棒性 |
| 机制/ODE | 单位 + 边界/极端情景 + 参数敏感性 + 已知规律检查 | 参数置信区间、外部校准 |
| 主体/随机仿真 | 多随机种子 + 汇总区间 + 基线情景 + 关键规则敏感性 | 校准、反事实情景 |
| 排序/评价 | 权重来源 + 标准化检查 + 权重敏感性 + 排名稳定性 | 多方法一致性、删除单指标测试 |
| 网络/空间 | 结构构建依据 + 基线网络/空间权重 + 扰动测试 | 空间自相关、尺度敏感性 |

## 3.1 灵敏度分析协议

仅在已确定模型规格、参数来源和输出指标后开展灵敏度分析。先记录代表性基准点以及每个参数的合法范围或分布；基准点不具代表性时，局部结论不得外推。局部诊断可使用一因子一变（OAT）：固定其他参数，对单个参数施加正负扰动，在多个扰动幅度上检查结论是否稳定。只有输入和输出基准均远离零时才使用相对变化比；遇到零或近零基准时，改报绝对变化、弹性在有定义区间内的结果，或使用有业务意义的尺度归一化。对可导模型可使用解析导数；对黑箱或不可导模型使用有限差分时，必须记录步长并检验步长变化不会改变排序结论。

若参数存在交互、模型明显非线性、结论依赖区间，或需要量化方差贡献，则改用全局方法。为参数指定有依据的分布，明确采样策略和样本量，并检验估计量随样本量增长的收敛性。可先用低成本筛选识别候选重要参数，再对保留参数进行方差分解或其他全局分析；不得把局部 OAT 排序误述为全局重要性。

| 报告项 | 最低要求 |
|---|---|
| 设定 | 基准点、参数范围/分布、扰动方向与幅度、输出指标及其来源。 |
| 局部结果 | 相对灵敏度定义、多个步长的稳定性、排序图及适用基准/区间。 |
| 全局结果 | 采样方法、样本数、收敛检查、主效应/总效应或等价指标，以及交互解释。 |
| 决策 | 高敏参数的优先测量/校准计划；低敏参数被固定或删减前的复验。 |
| 局限 | 不能覆盖的参数相关性、未建模的结构不确定性和外推风险。 |

把灵敏度结果回链到 `model-evidence-pack.md`、运行日志和图表生成脚本。对任何第三方实现先在已知小例子上复算，再用于关键结论。

## 4. 分层修复协议

遇到错误或可疑结果时，按下列顺序处理。每次修复只改动一层，并记录改动与影响。

1. **执行级修复：** 语法、依赖、索引、文件路径、API/求解器调用、图表渲染或随机种子问题。保留数学规格不变，添加最小单元测试后重跑。
2. **实现级修复：** 代码与数学规格不一致、维度/单位错误、变量域/约束遗漏、指标计算错误。修复后重新执行可行性和基线测试。
3. **规格级修复：** 无解、无界、不可识别、参数不可估、动态不稳定、预测目标定义不清。修改模型规格，更新语句—公式台账，重新实施与验证。
4. **问题级修复：** 子问题拆解、目标、假设或数据口径本身错误。回到题意和数据审计，重建候选比较表；不得只在代码层打补丁。

### 触发升级的信号

| 观察到的问题 | 首先检查 | 升级条件 |
|---|---|---|
| 代码报错 | 执行级 | 同类错误重复或修复后结果不合逻辑，转实现级 |
| 有解但违反现实规则 | 实现级 | 代码实现正确而规则本身不充分，转规格级 |
| 优化无解/无界 | 规格级 | 约束和目标均有业务来源但仍冲突，转问题级 |
| 模型拟合好但时间外失效 | 数据/规格级 | 不存在可用的无泄漏特征或目标定义不稳定，转问题级 |
| 多次随机仿真结论相反 | 实现级/规格级 | 增加重复仍不稳定，转问题级并降级结论 |

默认允许两次执行级、一次实现级修复。耗尽某层次数后，先回到上一层规格或问题定义重新审查；只有材料性输入、规则、权限或全局预算不足而无法继续时才 `escalate`。修复次数不是成功指标，必须以通过的验证门槛结束。

## 5. 语义审计清单

对模型中的每个变量、公式和结论提问：

- 这个对象在题意中对应什么？单位是否一致？
- 若其取零、取边界或达到极端值，结果是否合理？
- 删除这一约束或变量会发生什么？它是否真的必要？
- 参数来自数据、题设、文献还是主观设定？不确定性如何进入结论？
- 此结论是描述、预测、优化建议还是因果解释？证据是否匹配？

把问题按 `high / medium / low` 置信度列出。先修复高置信度、会改变结果的错误；把判断性分歧保留为替代方案，而不是伪装为事实。

## 6. 复现清单

```markdown
- [ ] 输入数据与版本已标识；字段和单位可追溯。
- [ ] 从原始输入到图表/表格的运行顺序已说明。
- [ ] 代码、包版本、求解器、随机种子和硬件/时间限制已记录。
- [ ] 关键参数、情景和模型变体可由配置文件重现。
- [ ] 求解状态、误差指标和失败运行被保留，而非只保留成功结果。
- [ ] 每个关键结论可定位到表、图、实验或公式。
```

## 7. 审计输出格式

创建 `<项目>_audit.md`，包含范围与输入、四层审计结果、高置信度问题表、中低置信度问题表、最小修复集、修复后复验清单和 outcome。将 `pass` 映射为 `completed`，将有明确残余风险但不阻断当前范围的 `pass-with-notes` 映射为 `partial`，将关键门禁失败的 `needs-revision` 映射为 `invalidated`；若缺少外部输入或权限，则使用 `blocked`。
