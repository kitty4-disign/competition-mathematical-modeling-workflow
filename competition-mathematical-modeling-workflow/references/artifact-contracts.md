# 工件契约与生命周期

把 `assets/templates/workflow-ledger.md` 作为项目的单一事实源。其他工件只保存其专业细节，并用稳定 ID 回链到台账；不要在多个文件中手工复制同一数值、状态或决定。

## 核心对象

| 对象 | ID 示例 | 唯一职责 | 何时建立 |
|---|---|---|---|
| 输入版本 | `I-data-v2` | 标识题目、规则、数据、假设或外部来源的不可变版本。 | 首次使用及任何材料性变更后。 |
| GateSpec | `G-design-03` | 保存判据、指标、阈值、切分/情景、证据和状态。 | 看结果前。 |
| 模型规格 | `M-T2-v3` | 定义变量、公式、约束、参数来源、算法和失效条件。 | 实现前。 |
| 运行 | `RUN-T2-014` | 绑定输入、规格、代码/环境、配置、种子、状态和输出。 | 每次正式或失败运行。 |
| 结果 | `R-T2-v5` | 指向由一次或多次运行生成的表、图或结构化指标。 | 运行完成后。 |
| 主张 | `C-T2-07` | 保存精确表述、完整证据链、适用范围、反证条件和强度。 | 结果解释或写作前。 |
| 决策 | `D-021` | 保存备选、选择理由、否决条件、影响对象和下一步。 | 选择、回退、豁免或停止时。 |

## 状态与转移

统一使用以下工件状态：

- `draft`：尚未完成门禁；不得进入论文主张。
- `candidate`：可执行或可验证，但尚未冻结。
- `frozen`：其输入、规格和门禁均固定，可供下游引用。
- `failed`：已运行但未通过；保留证据，不覆盖删除。
- `stale`：上游版本变化导致失效；不得继续引用。
- `rejected`：基于明确否决条件不再采用。

只有 `frozen` 的结果可支持摘要、结论和提交材料。任何上游对象变化时，沿依赖关系把全部下游对象标为 `stale`；创建新版本，不覆盖旧版本。重新运行并通过原 GateSpec 或新版本 GateSpec 后，才能再次冻结。

## 最小依赖图

```text
输入/规则/假设
  → 子问题与 GateSpec
  → 模型规格与实验计划
  → 代码/配置/运行
  → 结果
  → 验证
  → 主张
  → 图表/论文/提交包
```

在工作台账的依赖列中记录直接上游 ID。不要只用文件名表达依赖，因为文件内容可能变更。

## 专项工件

仅在能减少信息丢失时建立专项工件：

| 专项工件 | 使用条件 | 与台账的关系 |
|---|---|---|
| `model-evidence-pack.md` | 模型规格、实验或验证复杂，单表无法清楚表达。 | 保存专业细节；台账只保留模型/结果/主张 ID 与状态。 |
| `tool-evidence-log.md` | 外部事实、求解器、代码或连接器输出影响结论。 | 保存调用与原始状态；台账登记 Run ID 和独立检查。 |
| `competition-profile.md` | 任务涉及论文格式、匿名、文件包或正式提交。 | 只保存由当届官方来源核验的规则版本。 |
| 论文与图表模板 | 关键结果和主张已经冻结。 | 只引用结果/主张 ID，不重新计算或手抄数值。 |

不要为一次简短算法建议创建空白论文、提交清单或完整模型证据包。不要为一次确定性工具调用启动 Agent Loop。按请求模式只创建能承载实际证据的工件。

## 最低一致性检查

在阶段推进或交付前检查：

1. 每个 `frozen` 结果是否绑定不可变输入、规格、运行和 GateSpec；
2. 每个主张是否绑定结果与验证，而不是只绑定图表或公式；
3. 是否仍有 `stale` 或 `failed` 工件被论文、摘要或图表引用；
4. 同一数值是否由结构化结果生成，而不是在多份 Markdown 中手工维护；
5. 每个材料性决策是否记录备选、否决条件和影响的下游对象；
6. 最终提交是否能从论文主张逆向定位到原始输入版本。
