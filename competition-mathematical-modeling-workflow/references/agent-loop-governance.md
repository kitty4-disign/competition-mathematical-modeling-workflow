# 受控建模 Agent Loop

仅在任务需要多轮候选修复、跨会话恢复、显式自主迭代或预算化搜索时启用本协议。不要因为执行者是 Agent、调用了一次工具或运行了一次确定性计算就启动完整 Loop。

## 1. 启动条件

启动前在 `assets/templates/workflow-ledger.md` 中冻结：目标、当前阶段、单轮可改变对象、GateSpec、基线、最大迭代数、时间/工具/成本预算、允许工具、写入范围、敏感数据边界和停止条件。

若任务可由一次有界计算或一次审阅完成，直接执行主工作流并记录 Run ID，不建立迭代记录。

## 2. 每轮只获得一个可判定信息增量

按以下顺序运行：

```text
读取冻结状态 → 声明一个假设或最小变更 → 预期信息增益
→ 执行批准检查 → 独立复核 → 更新证据和依赖失效
→ advance / retry / rollback / escalate / stop(reason)
```

每轮只能改变一个主要假设、模型规格或实现因素。把输入版本、变更、检查、资源消耗、通过/失败证据、下游 `stale` 对象、决策和下一步唯一动作写入工作台账；不要依赖对话上下文承担长期状态。

## 3. 分离阶段决策与最终 outcome

| 阶段决策 | 允许条件 | 必须动作 |
|---|---|---|
| `advance` | 当前阶段全部必做 GateSpec 为 `pass` 或有合格 `waived`。 | 冻结工件并进入下一阶段。 |
| `retry` | 存在一个明确、低风险、可检验且仍在该层预算内的失败原因。 | 只改一个因素，保留失败运行后复验。 |
| `rollback` | 候选低于基线、违反硬约束、污染验证或断开证据链。 | 恢复最近冻结基线，将受影响下游标为 `stale`。 |
| `escalate` | 材料性输入、规则、权限或全局预算不足，无法安全继续。 | 停止自动动作，列出缺口、风险、已有证据和需要的决定。 |
| `stop(reason)` | 目标完成、全局预算耗尽或任务被终止。 | 使用 `completed`、`budget-exhausted` 或 `aborted` 原因。 |

另行记录 outcome：`completed`、`partial`、`blocked` 或 `invalidated`。不要用 `stop` 同时表示成功和失败。

## 4. 修复层级与无进展

| 失败类别 | 唯一路由 |
|---|---|
| 路径、依赖、语法、调用参数 | 执行级修复；默认最多两次。 |
| 代码与既定数学规格不一致 | 实现级修复；默认最多一次。 |
| 无解、无界、不可识别、动态不稳 | 回到规格级，创建新模型版本。 |
| 目标、约束、假设或数据口径错误 | 回到问题/输入层，重建下游依赖。 |
| 只有论文措辞超过证据 | 删除或降级主张；不要重建正确模型。 |

耗尽某层次数后回到上一层审查，不要继续更换提示词。只有因外部输入、权限或全局预算不足而无法继续时才 `escalate`。

连续两轮没有新增通过的 GateSpec，且失败类别相同或变更集合重复时，判定无进展并 `rollback`；若回退后仍缺少外部决定，再 `escalate`。

## 5. 独立复核的可执行含义

优先使用盲留出、由规格生成的小例子、不同实现/求解器、枚举、量纲/边界检查或未主导该模块的复核人。模型自评不是独立证据。无法获得真正独立检查时，把主张降为 `exploratory` 并记录原因，不要伪装为已复核。

## 6. 权限与退出

先用只读、确定性、低成本检查。仅在隔离环境和非敏感样本上运行已审阅代码；不把密钥、Cookie、个人信息、未公开赛题或敏感原始数据写入台账。外部写入、上传、提交、发布、排程或权限提升必须遵守当前环境的授权规则。

若无法提供合法最小输入、无法解释数学语义、无法完成最低验证，或循环耗尽全局预算仍没有可复现基线，停止采纳候选并输出 `blocked` 或 `invalidated`，同时保留失败证据与人工待办。
