# 仿真与不确定性实验设计

## 适用范围

当子问题依赖随机需求、到达/服务过程、个体异质性、传播、可靠性、风险、离散事件、系统反馈或政策情景时，使用本参考。它补充常规敏感性分析，要求把不确定输入如何传递为**结果分布与结论边界**讲清楚；不适用于仅有确定性参数的普通优化或回归任务。

先读取 `modular-task-routing.md`，并将仿真子问题登记在 `task-method-result-map.md`。代码执行、隔离、日志和外部数据要求仍由 `tool-enhanced-execution.md` 管理。

## 实验规格

开始运行前，建立下表；未知或无法识别的项不得用看似精确的默认值掩盖。

| 项目 | 必须说明 |
|---|---|
| 不确定性类型 | 区分随机波动、参数估计误差、模型结构不确定性和情景不确定性；不要将四者混为一个“误差项”。 |
| 随机输入 | 对每个随机变量给出含义、单位、分布/经验来源、参数、支持集、时间尺度及证据来源。 |
| 相关与依赖 | 写明独立、相关、条件相关或共同驱动关系；相关变量不得未经理由独立抽样。 |
| 确定性基线 | 先以均值/中位数或明确的典型情景运行模型，检查逻辑、单位、约束和极端行为。 |
| 随机控制 | 固定主随机种子以可复现；用额外种子复现实验。比较方案时，优先采用共同随机数或明确说明为何不能采用。 |
| 输出 | 至少定义均值之外的中位数、分位数/区间、超限概率、尾部风险、失败频率或其他与赛题直接相关的风险指标。 |
| 停止规则 | 预先定义模拟次数、批次大小和收敛准则，例如均值、关键分位数和尾部指标在连续批次间的变化阈值。 |

## 执行顺序

1. 在小规模、可手算或可直观检查的情景中验证随机机制与确定性基线；先确认实现正确，再追求模拟规模。
2. 逐批增加模拟次数，记录每批的均值、标准误、关键分位数、超限概率和运行时间；不要只根据一条均值曲线判断收敛。
3. 对稀有事件，评估有效事件样本量与区间宽度。样本不足时，只报告“无法稳定估计”，或采用并说明经过验证的方差缩减/专门抽样方法。
4. 对方案比较，保持输入情景、随机种子集合、总模拟次数和评价口径可比。若使用共同随机数，报告其作用是降低比较噪声，而不是增加独立样本量。
5. 分开进行参数敏感性与随机重复：前者回答“参数变化会怎样”，后者回答“在同一参数下随机波动多大”。不得将局部敏感性排序写成对所有不确定性的总体结论。
6. 将每次正式实验的输入版本、种子策略、运行状态、输出文件、收敛图和失败情况写入工具证据日志；固定一个结果版本后，才允许将数值写入论文。

## 验证与报告

| 检查 | 最低报告要求 |
|---|---|
| 分布合理性 | 说明为何分布、边界和离散化符合变量的非负性、上界、厚尾或机制；没有证据时改用情景范围并声明。 |
| 收敛 | 展示关键均值、分位数或尾部指标随批次/样本量变化的诊断，而不是只给最终模拟次数。 |
| 可复现性 | 报告主种子、重复种子集合、代码/输入版本、模拟次数和硬件/时间限制。 |
| 稳健性 | 至少比较一个替代分布、参数范围或情景，说明稳定结论与易变结论。 |
| 可解释性 | 说明不确定性来自哪里、怎样影响决策/预测，以及区间或概率不能证明什么。 |
| 图表 | 用区间、分布、箱线/密度、扇形带、超限概率或情景表表达不确定性；禁止只展示单条均值曲线来暗示稳定。 |

## 常见失效与处理

- **约束在随机情景中失效：** 分别报告可行率、违反类型和违反幅度；不要只报告平均可行。
- **运行超时或样本不足：** 先缩小模型、检查瓶颈、验证小规模输出，再采用分批运行或经说明的近似；不得把未收敛结果描述为稳定。
- **参数或结构不可识别：** 用情景区间替代单点校准，并将结论限定为条件性结果。
- **基线与仿真结论冲突：** 回查单位、随机机制、相关结构、数据抽样和实现，不要选择更“好看”的结果。

## 交付物

至少交付实验规格表、可运行脚本、输入版本说明、结果汇总表、收敛诊断、分布/区间图、重复或替代情景比较，以及一段阐明稳定范围和失败条件的解释。每个关键数值都应能通过结果标识回链到代码、日志和图表。
