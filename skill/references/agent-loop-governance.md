# 建模 Agent Loop 治理

将竞赛建模任务组织为**阶段内有限迭代、阶段间证据门禁**的闭环。Loop 的职责是生成有限候选、运行已批准检查、记录状态并在失败时路由；它不能替代题意理解、赛事规则核验、模型语义判断或人工终审。

## 1. 何时读取本参考

在以下情形先读取本文件并从 `templates/agent-loop-state.md` 建立状态文件：任务使用 LLM/Agent、需要多轮候选生成或修复、需要跨会话恢复、调用工具/连接器、或用户要求自动化/迭代优化。一次性、纯手工且无 Agent 的小任务可不建立完整 Loop，但仍须遵守主技能的证据与验证要求。

## 2. 每轮协议

每次迭代只处理一个明确子问题，按以下顺序运行：

```text
冻结输入与约束 → 提出一个候选或最小变更 → 执行批准的检查 → 独立复核
→ 更新状态、证据与决策日志 → advance / retry / rollback / escalate / stop
```

冻结项包括题目版本、赛事规则、数据/字段口径、代码或参数版本、允许工具、允许写入范围和预声明验收条件。每轮必须将输入摘要、候选、检查结果、资源消耗、进展信号和下一步写入状态文件；不要依赖对话上下文承担长期记忆。

## 3. 五种决策

| 决策 | 触发条件 | 必须动作 |
|---|---|---|
| `advance` | 当前阶段全部证据门禁通过。 | 冻结工件，记录通过依据，转入下一阶段。 |
| `retry` | 存在明确、低风险且处于允许修复层级内的失败原因。 | 只修改一个主要候选或修复层，保留上轮证据后复验。 |
| `rollback` | 新候选不如基线、违反硬约束或使证据链断裂。 | 恢复最近冻结的可复现基线，保留失败运行。 |
| `escalate` | 关键输入不足、规则不清、权限不足、高风险操作或修复层级耗尽。 | 停止自动动作，向用户说明所缺信息、风险和已有证据。 |
| `stop` | 目标达到，或达到预先声明的轮数/时间/工具配额。 | 写明停止理由、完成/未完成状态和后续人工动作。 |

## 4. 分层修复与无进展检测

默认最多允许两次**执行级**修复（路径、依赖、语法、参数、工具调用）和一次**实现级**修复（代码未实现既定规格、指标计算错误）。超过上限时，按 `verification-and-repair.md` 依次回溯到规格级或问题级，而不是继续更换提示词或重复同类工具调用。

将以下任一情形视为无进展：连续两轮得到相同失败类别且没有新增通过检查；变更集合重复而关键指标未改善；或候选只改变表述、不改变可检验假设/公式/实现。无进展时执行 `escalate` 或 `rollback`，不得无限重试。

## 5. 阶段门禁

| 阶段 | 进入下一阶段前必须具备 | 常见失败路由 |
|---|---|---|
| 题意与数据 | 问题定义、变量/数据字典、假设、数据质量记录和子问题路线。 | 关键数据/规则缺失：`escalate`。 |
| 模型选择 | 候选比较、可审计模型规格、验证计划及失效条件。 | 变量/公式语义不清：规格级回退。 |
| 实现与实验 | 可复现基线、环境/参数/输入版本、失败日志和模块级测试。 | 运行/依赖问题：执行级；规格不一致：实现级。 |
| 验证与稳健性 | 预声明的最低验证组合、证据矩阵、局限和反例/边界检查。 | 泄漏、不可复核结论或测试集调参：回退至数据/规格。 |
| 论文与提交 | 冻结结果、需求—方法—结果映射、图表/正文一致性和合规清单。 | 主张无证据或格式规则未核验：`retry` 或 `escalate`。 |

## 6. 权限、成本与人工闸门

先使用确定性检查、可复现计算和外部状态，再使用模型自评。每个 Loop 预先声明最大迭代次数、时间/工具预算和允许工具。只在隔离环境和非敏感小样本上运行已审阅代码；不得把密钥、Cookie、个人信息、未公开赛题或原始敏感数据写入状态/日志或上传到第三方。

除非用户明确授权并已展示操作摘要，否则不进行外部写入、提交、发布、排程或权限提升。赛事规则、模型选择、关键假设、最终结论和论文提交必须保留人工判断；无独立验证的 Agent 输出只能作为待查候选。

## 7. 与现有工件的关系

状态文件只记录“本轮在哪里、做了什么、是否继续”；它不替代以下工件：

| 工件 | 继续承担的职责 |
|---|---|
| `model-evidence-pack.md` | 模型假设、规格、实验、验证和主张的完整证据链。 |
| `tool-evidence-log.md` | 影响结论的工具调用、输入、权限、输出和独立检查。 |
| `decision_log` | 模型选择、参数口径和被排除替代方案。 |
| `task-method-result-map.md` | 题目要求到方法、结果、验证和论文位置的映射。 |

## 8. 退出条件

停止采纳任何 Agent 输出并请求人工介入，若无法提供合法最小输入、无法解释其数学语义、无法完成独立检查、需要越权操作，或循环耗尽资源仍未形成可复现基线。将此类结果标记为“待验证”或“未完成”，不要写入论文核心结论。
