# 验证、审计与分层修复

将验证设计为独立阶段，而不是论文末尾的装饰。每一项关键结论必须有**证据类型、复算路径、失败条件和修复动作**。

## 1. 证据矩阵

对每个关键主张建立记录；无法填满的主张必须降级为假设、探索性发现或待验证结论。

| 主张 ID | 主张 | 证据类型 | 输入/公式/实验 | 指标或判据 | 结论强度 | 失效条件 |
|---|---|---|---|---|---|---|
| C1 | 例如：方案 A 比基线节约成本 | 优化/情景实验 | 实验 E3、约束集 v2 | 成本差、可行性 | 强/中/弱 | 需求超出情景范围 |

证据类型可取：代数推导、数据描述、交叉验证、时间外测试、可行性检查、基线对比、情景仿真、灵敏度分析、外部事实核对。不要用同一训练数据上的拟合优度同时证明预测能力和机制真实性。

## 2. 四层审计

按顺序审计；前一层不通过时，不要用后一层结果掩盖问题。

### 层 A：输入与数据审计

检查文件版本、字段含义、单位、重复记录、缺失机制、异常、样本选择、时间泄漏和数据变换。输出“数据问题—处理—残余风险”表。

### 层 B：模型语义审计

检查题意—变量—目标—约束映射；变量域与单位；目标方向；边界和初值；参数的估计来源；模型何时会产生不合理行为。使用 `references/model-selection-atlas.md` 中的语句—公式台账。

### 层 C：计算与求解审计

检查代码是否实现同一数学模型；随机种子和环境；求解器状态；终止条件；数值尺度；性能瓶颈；图表是否由当前结果生成。对优化问题记录 `optimal / feasible / infeasible / unbounded / time-limit / error`，不得仅报告一个数值。

### 层 D：结论与叙事审计

检查每个结论是否由证据矩阵支持；图表与正文是否一致；是否把相关写成因果；是否夸大外推；局限是否与假设和数据风险对应；论文是否回答全部子问题。

## 3. 最小验证组合

按任务类型至少完成以下组合。

| 任务 | 最低组合 | 优先补充 |
|---|---|---|
| 预测/分类 | 合理切分 + 基线 + 两个指标 + 误差检查 | 校准、分组性能、时间外测试 |
| 优化 | 可行性 + 基线比较 + 求解状态 + 权重/参数敏感性 | ε-约束/Pareto、情景/鲁棒性 |
| 机制/ODE | 单位 + 边界/极端情景 + 参数敏感性 + 已知规律检查 | 参数置信区间、外部校准 |
| 主体/随机仿真 | 多随机种子 + 汇总区间 + 基线情景 + 关键规则敏感性 | 校准、反事实情景 |
| 排序/评价 | 权重来源 + 标准化检查 + 权重敏感性 + 排名稳定性 | 多方法一致性、删除单指标测试 |
| 网络/空间 | 结构构建依据 + 基线网络/空间权重 + 扰动测试 | 空间自相关、尺度敏感性 |

## 3.1 灵敏度分析协议

仅在已确定模型规格、参数来源和输出指标后开展灵敏度分析。先记录代表性基准点以及每个参数的合法范围或分布；基准点不具代表性时，局部结论不得外推。局部诊断可使用一因子一变（OAT）：固定其他参数，对单个参数施加正负相对扰动，计算输入和输出的相对变化比，并在多个扰动幅度上检查结论是否稳定。对可导模型可使用解析导数；对黑箱或不可导模型使用有限差分时，必须记录步长并检验步长变化不会改变排序结论。

若参数存在交互、模型明显非线性、结论依赖区间，或需要量化方差贡献，则改用全局方法。为参数指定有依据的分布，明确采样策略和样本量，并检验估计量随样本量增长的收敛性。可先用低成本筛选识别候选重要参数，再对保留参数进行方差分解或其他全局分析；不得把局部 OAT 排序误述为全局重要性。

| 报告项 | 最低要求 |
|---|---|
| 设定 | 基准点、参数范围/分布、扰动方向与幅度、输出指标及其来源。 |
| 局部结果 | 相对灵敏度定义、多个步长的稳定性、排序图及适用基准/区间。 |
| 全局结果 | 采样方法、样本数、收敛检查、主效应/总效应或等价指标，以及交互解释。 |
| 决策 | 高敏参数的优先测量/校准计划；低敏参数被固定或删减前的复验。 |
| 局限 | 不能覆盖的参数相关性、未建模的结构不确定性和外推风险。 |

把灵敏度结果回链到 `model-evidence-pack.md`、运行日志和图表生成脚本。对任何第三方实现先在已知小例子上复算，再用于关键结论。

## 3.2 残差自相关自动修正与回退

仅对具有严格时间顺序的预测任务启用。自动化的职责是**生成并检验有限的修正候选**，不是在最终测试期上反复调参，也不是保证修正一定成功。先在训练期完成时间对齐、泄漏、异常、季节性和结构断点审计；若这些前置检查不通过，直接回到数据或规格层，不拟合残差修正。

### 触发与候选

在训练残差上按预先声明的滞后集合做 ACF 和适当的白噪声检验；诊断显示异常时，建立下表。始终保留 R0；候选滞后与季节周期必须在查看最终测试期前固定。非季节残差 AR 的默认最大阶数为 `min(5, floor(n_train/10))`；只有历史覆盖至少三个完整周期且季节诊断触发时，才允许季节残差候选。

| 候选 | 适用条件 | 修正与边界 |
|---|---|---|
| R0：无修正 | 始终保留。 | 原主模型预测，作为回退和比较基线。 |
| R1：低阶 AR 残差 | 存在低阶残差相关，且训练长度支持预设滞后。 | 仅使用训练残差递归预测未来误差，再加回主模型预测；记录残差定义、滞后和初值。 |
| R2：季节残差修正 | 季节滞后异常且历史覆盖足够周期。 | 只加入预设季节项；不得通过穷举大量滞后寻找测试期最优结果。 |
| R3：动态重规格 | R1/R2 未通过或怀疑结构问题。 | 把状态空间、动态回归或其他含误差结构的模型作为**新候选**，重新完成候选准入和比较。 |

### 选择、接受与回退

在训练期内部使用滚动原点验证选择 R0–R3；数据允许时至少使用两个验证原点，否则记录只有一个内部留出窗的限制。先固定主指标和最小实用改善阈值 `Δ_min`；题目未给出时，默认要求相对 R0 至少改善 2%。候选只有同时满足下列条件才可进入最终时间外确认：

1. 未使用最终测试期、未来目标或未来残差；
2. 在内部滚动验证的主指标上达到 `Δ_min`；
3. 修正后的验证残差不再触发同一严重自相关信号，或残余信号已被明确限界；
4. 无数值不稳定、硬约束违反或无法复现的实现；
5. 候选复杂度与数据量、计算资源相称。

冻结选择后，最终时间外测试只运行一次。若没有候选通过，保留 R0，并把结果判为 `pass-with-notes` 或 `needs-revision`；不得为了消除残差相关而采纳验证较差的模型。若修正失败源于数据错位、断点、遗漏季节性或目标定义错误，按第 4 节升级，而不是继续堆叠残差项。

### 必须记录

| 项目 | 最低记录 |
|---|---|
| 触发 | 残差定义、训练窗、诊断方法、滞后集合、阈值与结果。 |
| 前置审计 | 时间对齐、泄漏、异常、季节性、断点和可用历史长度。 |
| 候选 | R0–R3、滞后/周期、参数、求解状态和失败运行。 |
| 内部选择 | 每个滚动窗的指标、相对 R0 的改善、残差诊断和接受/拒绝理由。 |
| 最终确认 | 冻结后的最终测试指标、边界检查、结论级别和回退状态。 |

## 4. 分层修复协议

遇到错误或可疑结果时，按下列顺序处理。每次修复只改动一层，并记录改动与影响。

1. **执行级修复：** 语法、依赖、索引、文件路径、API/求解器调用、图表渲染或随机种子问题。保留数学规格不变，添加最小单元测试后重跑。
2. **实现级修复：** 代码与数学规格不一致、维度/单位错误、变量域/约束遗漏、指标计算错误。修复后重新执行可行性和基线测试。
3. **规格级修复：** 无解、无界、不可识别、参数不可估、动态不稳定、预测目标定义不清。修改模型规格，更新语句—公式台账，重新实施与验证。
4. **问题级修复：** 子问题拆解、目标、假设或数据口径本身错误。回到题意和数据审计，重建候选比较表；不得只在代码层打补丁。

### 触发升级的信号

| 观察到的问题 | 首先检查 | 升级条件 |
|---|---|---|
| 代码报错 | 执行级 | 同类错误重复或修复后结果不合逻辑，转实现级 |
| 有解但违反现实规则 | 实现级 | 代码实现正确而规则本身不充分，转规格级 |
| 优化无解/无界 | 规格级 | 约束和目标均有业务来源但仍冲突，转问题级 |
| 模型拟合好但时间外失效 | 数据/规格级 | 不存在可用的无泄漏特征或目标定义不稳定，转问题级 |
| 多次随机仿真结论相反 | 实现级/规格级 | 增加重复仍不稳定，转问题级并降级结论 |

默认允许两次执行级、一次实现级修复；超过此范围必须重新审查数学规格。修复次数不是成功指标，必须以通过的验证门槛结束。

## 5. 语义审计清单

对模型中的每个变量、公式和结论提问：

- 这个对象在题意中对应什么？单位是否一致？
- 若其取零、取边界或达到极端值，结果是否合理？
- 删除这一约束或变量会发生什么？它是否真的必要？
- 参数来自数据、题设、文献还是主观设定？不确定性如何进入结论？
- 此结论是描述、预测、优化建议还是因果解释？证据是否匹配？

把问题按 `high / medium / low` 置信度列出。先修复高置信度、会改变结果的错误；把判断性分歧保留为替代方案，而不是伪装为事实。

## 6. 复现清单

```markdown
- [ ] 输入数据与版本已标识；字段和单位可追溯。
- [ ] 从原始输入到图表/表格的运行顺序已说明。
- [ ] 代码、包版本、求解器、随机种子和硬件/时间限制已记录。
- [ ] 关键参数、情景和模型变体可由配置文件重现。
- [ ] 求解状态、误差指标和失败运行被保留，而非只保留成功结果。
- [ ] 每个关键结论可定位到表、图、实验或公式。
```

## 7. 审计输出格式

创建 `<项目>_audit.md`，必须包含：范围与输入、四层审计结果、高置信度问题表、中低置信度问题表、最小修复集、修复后复验清单、最终判定（`pass`、`pass-with-notes` 或 `needs-revision`）。
