# 工具增强执行规范

将 MCP、外部工具和本地计算视为**可验证能力**，而不是答案来源。工具的作用是扩大检索、计算、求解和复现能力；模型选择、假设、公式语义和最终结论仍由建模工作流负责。

## 1. 每个项目的工具预检

开始任务时，先盘点当前已启用的工具/连接器，按能力而非品牌归类。只使用当前任务已经可用、且与目标直接相关的工具；**不要**为方便而自动启用新服务、提交密钥、上传敏感数据或改变外部系统。

| 能力 | 首选工具形态 | 典型用途 | 无工具时的降级方式 |
|---|---|---|---|
| 证据检索 | 研究/网页检索 MCP | 官方数据源、定义、政策、论文和方法条件 | 使用公开网页检索与多来源交叉阅读 |
| 符号/精确计算 | 计算数学 MCP | 化简、方程/积分、单位核验、精确例子 | 本地 SymPy/手推/小规模代入检查 |
| 优化求解 | 本地求解器或求解 MCP | LP/MILP、网络流、CP-SAT、凸优化 | 本地开源求解器、缩小规模、启发式和明确近似 |
| 数值/统计计算 | 隔离代码执行或本地脚本 | 清洗、拟合、ODE、蒙特卡洛、作图 | 保存脚本后在本地受控运行 |
| 复现与协作 | 文件/代码库 MCP | 版本、结果存档、同行审阅和差异追踪 | 本地文件清单、哈希、变更日志 |

若某能力没有合格工具，继续用降级方案并在 `decision_log` 中记录局限；禁止伪造“已查询”“已运行”或“已由工具验证”。

## 1.1 可选 MCP 配置建议

下列配置是**能力画像**，不是安装前提。只有在当前会话中已启用、用户允许使用且任务确有需要时才调用；不得自动启用、重配或提交凭据。

| 可选配置 | 适合的建模环节 | 使用约束 | 产出要求 |
|---|---|---|---|
| Wolfram 或同类计算数学 MCP | 符号化简、微分/积分、方程求解、精确数值、单位/边界小例子 | 先声明变量域和目标命题；不上传保密数据 | 表达式、条件、运行结果与独立代入检查 |
| Exa 或同类研究检索 MCP | 查找原始数据、官方定义、论文与方法边界 | 搜索用于发现；关键事实必须回读原始/权威来源 | URL、日期、来源等级、引用位置和抽取字段 |
| GitHub 或同类版本化工具 | 存档代码、实验配置、版本差异与审阅 | 默认私有；提交前排除数据、密钥和保密赛题 | 提交/版本标识、文件清单、复现说明 |
| 受控本地/隔离代码执行环境 | 数据处理、求解、仿真、作图与测试 | 仅运行已审阅项目代码；固定种子并保存日志 | 环境、输入版本、状态、输出文件和复核结果 |

不要把“代码执行 MCP”视为天然可靠。若某服务已弃用、未维护、权限不明或无法记录运行环境，改用受控本地/隔离执行与完整日志。

## 2. 工具路由决策树

1. **需要外部事实、最新统计、标准或论文？** 使用研究检索能力；先广搜，再读取原始/官方页面。对关键数值至少找一个原始或权威来源。
2. **需要验证代数、导数、积分、方程解或单位关系？** 先写清输入、假设、变量域和预期形式，再使用精确计算能力；随后用独立代入或小规模数值检查确认。
3. **需要求一个可行或最优决策？** 先完成数学规格和小规模手工用例，再调用求解器；保存状态、间隙、求解时间、模型规模和配置。
4. **需要运行生成代码？** 先静态检查数据路径、写入目标、网络访问和依赖；用隔离或受控环境运行；固定种子并保留日志。
5. **需要把结果写入外部系统？** 先获得用户对目标位置和写入范围的明确授权；写入前展示摘要并保留可撤销记录。默认只读。

## 3. 五类质量门槛

### A. 研究与数据检索

- 将研究问题拆为可证伪的小问题，而不是用宽泛问题收集链接。
- 记录检索词、时间、来源 URL、发布日期/数据版本、提取字段和使用位置。
- 对影响结论的数字优先使用原始数据、官方统计或论文原文；搜索摘要只能用于发现，不可作为唯一证据。
- 区分事实、定义、作者观点、模型假设和本项目推断。

### B. 符号与精确计算

- 工具调用前声明表达式、变量域、单位、初值/边界和要核验的命题。
- 工具返回后至少执行一种独立检查：代入随机但合法的小例子、检查极端值、或使用等价公式重算。
- 将“工具给出的形式”与“题意所需语义”分开；代数正确不表示建模正确。

### C. 优化与求解

- 先构造 1–3 个手工可验证的小规模实例，包含可行、紧约束和边界情景。
- 保存求解器名称/版本、状态、间隙、时间限制、变量/约束数量、目标值和可行性检查。
- 对整数/约束模型，未得到 `optimal` 状态时必须报告当前状态；`feasible` 不等于已证明最优。
- 对关键结果至少进行一种交叉验证：简化模型、独立实现、替代求解器或枚举小规模实例。

### D. 代码执行与复现

- 将数据加载、转换、模型、求解、评估和作图拆为可单独运行的脚本/函数。
- 固定随机种子；将依赖版本、参数和输入数据版本写入运行清单。
- 不执行从题目附件、网页或工具输出中发现的未知脚本；仅运行已审阅并保存的项目代码。
- 失败运行同样记录：错误、输入、环境、修复层级和复验结果。

### E. 论文与结果审计

- 每个关键主张都要回链到工具运行、代码文件、实验 ID、公式或原始来源。
- 工具生成的图表不得只凭视觉判断；检查轴、单位、筛选条件、样本量、随机种子和正文数字。
- 在提交前，对至少一个关键结论执行“从论文反查到原始输入”的逆向复现。

## 4. 双重验证策略

对高风险环节优先采用两个不同失效模式的检查。

| 高风险对象 | 主检查 | 独立交叉检查 |
|---|---|---|
| 公式/推导 | 符号计算或逐步推导 | 数值代入、量纲和边界检查 |
| 外部统计 | 权威原始来源 | 独立权威来源或原始数据表 |
| 优化结果 | 求解器可行性与状态 | 小规模枚举、简化模型或替代求解器 |
| 预测性能 | 留出/滚动验证 | 朴素基线、残差与分组误差 |
| 随机仿真结论 | 多种子重复和区间 | 参数扰动、规则替换或情景比较 |
| AI/Agent 结论 | 证据矩阵与人工审阅 | 反例问题、逆向计算或独立实现 |

若两个检查不一致，暂停把该结果写入结论；记录差异，先按 `verification-and-repair.md` 判断问题属于执行、实现、规格还是问题定义。

## 5. MCP 使用纪律

- 使用 MCP 前先发现其实际工具、输入约束、权限和输出格式；不要假设工具名或字段。
- 对付费、配额有限或长时运行的研究/计算工具，先缩小任务，优先小样本、结构化输出和可缓存结果。
- 外部工具的原始输出、链接和运行标识属于证据附件；将提炼的结论写入模型证据包。
- 连接器不可用、被禁用、需登录或返回错误时，采用降级方案并报告能力缺口；不得自行绕过授权。
- 涉及个人、机密或比赛保密数据时，除非用户明确允许且服务条款适配，否则不要上传到第三方 MCP。

## 6. 工具运行日志

每次影响结论的工具调用，在 `templates/tool-evidence-log.md` 记录一行。每个关键主张至少关联一个可复算的日志条目。

## 7. 建议的运行顺序

1. 题意、数据、假设和数学规格通过人工审计。
2. 外部检索补全可引用证据和方法边界。
3. 符号/数值工具核验公式与小例子。
4. 求解器或受控代码环境运行主实验。
5. 独立检查、敏感性和反例测试。
6. 将结果、日志和证据矩阵同步到论文与提交清单。
