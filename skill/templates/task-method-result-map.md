## 填写规则

1. **需求 ID / 原题位置：** 引用题目问题编号、段落或附件位置，避免把背景叙述误当强制要求。
2. **输入与假设版本：** 写入数据快照、关键口径和假设版本；假设改变后更新版本而非覆盖原记录。
3. **方法与模型版本：** 指向模型规格、脚本/Notebook、求解器配置或算法版本；不要只写“使用机器学习”“建立优化模型”。
4. **结果工件 ID / 文件：** 填入可复算的表格、JSON/CSV、图或日志标识，例如 `R-T2-sim-v2`；正文数字不得脱离此项手工维护。
5. **验证与反例检查：** 填入基线、留出/滚动验证、可行性、极端情景、敏感性、重复种子或替代模型等实际完成的检查。
6. **可支持的主张与边界：** 用条件化的陈述写清结果回答什么，以及不能证明什么。无验证的结果不能标为“已支持”。
7. **状态：** 使用“待开始 / 运行中 / 待验证 / 已冻结 / 不采用”。只有结果、验证和论文位置都确认后，才标记“已冻结”。

## 导出前核对

- 每一个赛题要求是否都有方法、结果、验证和论文位置？
- 每张表图是否存在对应需求、结果工件和一句可支持的主张？
- 是否有未通过验证、未收敛或已弃用的结果被写进正文或摘要？
- 摘要、结论和建议是否只引用状态为“已冻结”的结果？
- Word、PDF 或其他格式是否由同一经审阅的源稿和同一结果工件生成？
